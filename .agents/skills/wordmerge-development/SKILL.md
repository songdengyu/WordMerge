# WordMerge 开发经验

此 skill 随仓库维护。以下路径相对本目录；先确认工作目录是 WordMerge，原 TitanDemo 仅用作溯源。新用户需求可以改变继承规则，不以旧规则阻止新玩法。

## 按任务读取

- 玩法改造：先看 [新游戏记录](../../../docs/NEW-GAME.md) 与 [已确认策划规则](../../../docs/design/CORE-RULES.md)，再按需查 [继承规则](../../../docs/GAME-BASELINE.md)。区分已确认规则、待试玩数值与本轮讨论建议；WordMerge 仅为工程名。
- 模块定位、数值或美术：查 [工程说明](../../../docs/DEVELOPMENT.md)。运行 CSV 在 `public/config/`，归档表不是运行输入。
- 新游戏架构与实施：查 [技术方案](../../../docs/TECHNICAL-PLAN.md)。H5 优先，React UI 与 Pixi 地图共享独立 Runtime；方案与已实现代码分开判断。
- UI、拖拽、暂停、发奖或快照：查 [开发经验](../../../docs/LESSONS.md) 中相关项。
- 需求冲突：查 [历史演变](../../../docs/history/DECISIONS.md)；只在需要精确原话时打开对应会话档案，不整库加载。

## 改动时保留的关键约束

1. 旧基线的二级页暂停战斗；新游戏明确改为合成时世界继续、离线世界暂停而体力照常恢复。改造以新规则为准，处理旧战斗死亡 / 出生回调和组件挂载的依赖。
2. 合成操作由 reducer 提交，拖动浮层只是视觉；取消与无效落点不得丢棋子。生成器单击、特殊棋子双击是当前基线的不同入口。
3. 配置接入保留装备选择 / 替换等已有交互。`icon` 与 `iconName` 分别对应 SVG 文件和 symbol，检查渲染组件白名单及 viewBox。
4. 合成局部 `gems` 对应全局 `diamonds`。共享资源、订单奖励、effect 去重与快照一起考虑；内存快照不等于刷新后存档。
5. 新游戏物品只保留棋盘与仓库，无额外背包；建造订单统计两处物品。开工后不可中断，主角与当前部件无敌。体力自然恢复上限 100，道具可突破；这些明确修订优先于前期候选方案。

改完按范围验证：代码至少通过 `npm run build`，交互改动检查实际页面，CSV / SVG 检查运行时读取及引用。文档变动无需额外搭建测试。报告实际完成与未验证范围，并把新游戏已确认决策写入文档；历史档案保留原义。
