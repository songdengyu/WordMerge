# 怪物追击与房屋寻路性能

日期：2026-10-10。

## 原因与实现

怪物每 0.5 秒重新决策。主角处于封闭房屋时，原逻辑先搜索无法到达的主角 / 室内目标，再分别搜索每段墙、地板和屋顶的工作格；多个部件共用同一格也重复搜索。不可达目标会让同步 A* 遍历整片连通地面，九地块全部开放后尤其明显。

- `navigationCache.ts` 按不可变通行拓扑缓存地面、四向边和连通分区。隔着完整墙门、处于不同分区的目标直接判定不可达，保留原 A* 和连续碰撞检测处理同一分区内的路径。四向连通是当前禁止切角八向移动的必要条件，不会允许穿墙 / 斜切角。
- `constructionNavigation` 以 `WorldMap` 实例及真实阻挡边集合为缓存键。仅扣耐久且墙仍完整时复用；墙门破坏 / 修复 / 新建改变阻挡边即使用另一份缓存。砍树、开地派生新 `WorldMap`，自动重新计算。每个地图实例最多保留四种拓扑；旧地图通过弱引用回收。
- 常驻野猪使用独立的区域限制缓存，不能通过区域外绕路。自定义动态地图方法不使用缓存，继续按原规则即时检查。
- `planEnemy` 在一次决策内按导航与精确目的地复用成功 / 失败路径；同一站位不重复搜索。用直线距离下界跳过不可能更近的建筑候选，并直接复用胜出候选的路径，保留原先相同距离时的选择顺序。

不调整决策频率、怪物速度、攻击间隔、伤害、伙伴交战、施工与保存规则。不修改配置指纹或存档格式，不清档。缓存是派生数据，不能作为 Runtime 权威状态保存；以后新增动态障碍必须切换地图 / 阻挡边拓扑，或显式绕过缓存。

## 可重复的逻辑耗时比较

运行 `node scripts/benchmark-enemy-navigation.mjs`；可附输出 JSON 路径。使用相同电脑、五只游荡野猪、固定主角位置和完整建筑，移除资源物件以隔离墙门寻路；四次相同初始状态的决策，包含首次冷缓存。大屋场景开放全部九块地图。这里测 `advanceSurvival` 单步 CPU 耗时，不是帧率或真机测试。

| 场景 | 修改前平均 | 修改后平均 | 路径查询数 / 决策，前 → 后 |
|---|---:|---:|---:|
| 营地室外 | 2.94 ms | 1.49 ms | 5 → 5 |
| 营地小木屋内 | 243.30 ms | 1.85 ms | 179 → 48 |
| 九地块大屋内 | 5381.15 ms | 2.36 ms | 399 → 114 |

修改后首次冷缓存分别约 4.02 / 4.11 / 4.12 ms。剩余查询包含连通性立即拒绝，不等于完整 A* 搜索次数；数字会随机器与运行负载浮动。原始本机比较保存在忽略目录 `.local/ai-performance-before.json` 和 `.local/ai-performance-after.json`。

- `npm test`：32 文件 / 266 项通过，包含三日模拟、移动、区域、建筑分段、伙伴交战及旧档校验。新增四项拓扑回归覆盖反复不可达搜索、墙体扣血 / 破坏 / 修复、开地 / 清理与负坐标、常驻怪区域限制；原动态障碍用例保持通过。
- 浏览器既有两项回归通过：合成期间攻击 / 后台暂停 / 破门后伙伴战斗 / 刷新损伤保持，以及烟尘交战 / 实际扣血 / 结算不重复。

- 共三项相关浏览器流程通过。浏览器使用隔离上下文的测试存档，不接触玩家存档。
