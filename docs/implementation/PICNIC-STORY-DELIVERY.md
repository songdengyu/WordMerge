# 野餐委托与主线衔接

2026-10-10。

问题：委托 2「准备野餐」与剧情 `visitor` 都要求 212 果酱和 222 饮水。原实现只在委托记录完成，扣掉材料后，剧情仍检查库存并在回应时再次扣料。

`progression.ts` 用 `chapterCommission` 明确关联两者，`chapterDelivered` 读取已有 `inventory.completedOrders`，`chapterMaterials` 统一判断主线尚需交付的材料。已交付则不再扣料；未交付保留直接持材料阅读、回应时交付的流程。目录校验检查关联委托与主线材料匹配，不靠名称或物品相似度推断其他任务。

交付记录可早于主线和探索；它只满足物资要求，不跳过前置章节、溪谷发现或剧情选择。合成界面正常提交 / 测试完成关联委托后，若主线条件全部满足则打开对话并退出合成。回应后才保存选择、完成章节并发放原剧情奖励；委托奖励保持原规则且不重复发放。满棋盘无法领取工作台时保留交付记录，整理后可继续。

旧存档已经保存委托完成记录，直接认可，无需新增字段、配置指纹或清档。手记标记物资已交付，地图提示目标完成；从主线前往合成时聚焦“准备野餐”订单。

构建及 297 项规则测试通过，新增覆盖正常 / 测试交付、旧档认可与刷新、再次持有相同物资不扣、提前交付不跳前置、满棋盘保留记录、奖励只发一次。

两项 Chromium 流程通过：合成提交野餐后自动接入剧情、刷新继续对话、回应后进入下一章节并保持奖励；既有交付记录在手记显示已完成且可继续故事。首次用例因“✧ 合成物资”的精确名称定位不匹配而超时，调整测试定位后通过，未修改该按钮。使用独立测试存档，未操作玩家进度。
