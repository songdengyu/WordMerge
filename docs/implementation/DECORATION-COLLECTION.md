# 装饰系统与摆件库存

2026-10-07，已实现。

## 玩家入口

地图右下角新增“装饰”圆形按钮，紧邻“建造”，商店按钮移到它左边。营地手记删除原“装扮”分页，剧情中需要装扮的目标跳转到新系统。

装饰面板分为三页：

- **摆件**：展示已获得的摆件、可用库存和已摆放数量。点击摆放进入地图预览，确认后库存减 1，取消预览不扣库存。
- **人物皮肤**：展示已拥有的衣裳，点击换装；皮肤永久解锁，不消耗数量。
- **已摆放**：按独立实例列出物件及坐标，可以移动指定实例，或收回指定一件、库存加 1。

商店、剧情奖励获得的摆件和皮肤都在此管理。商店同款摆件可反复购买，每次扣对应价格并增加一件库存；图纸、生成器、人物皮肤继续沿用一次性解锁。皮肤购买后的按钮进入装饰收藏，商店另有“打开装饰收藏”入口。

摆件库存和同款同时摆放数量没有玩法上限；实际摆放仍需要有空闲的已建地板，一格最多一件，并保留床位。物件不增加战力或阻挡移动。进入收藏面板不暂停世界，剧情和失败时关闭面板。

## 数据与命令

- `ProgressionState.ownedDecor` 保留为曾获得的种类列表；`decorStock` 记录各类尚未摆放的数量，零库存保留键。
- `decorations` 数组中的每件物品新增独立 `id`（`d1`、`d2`……）；`nextDecorationId` 单调递增。Pixi 直接绘制完整实例列表，相同种类可共存。
- `decor-place` 不带 `decorationId` 时检查库存、位置并原子扣 1、创建实例；带 ID 时只移动目标实例，不改变库存。
- `decor-remove` 指定实例 ID，只收回该实例并返还库存。重复收回拒绝，不额外加数量。兼容旧命令仅有 kind 的情况时，必须只有一个匹配实例，否则拒绝歧义操作。
- `shop-buy` 对摆件允许重复成交，但 `economy.purchases` 仍为去重的商品来源记录。每次实际成交由 Runtime 一次性扣币、加库存和保存。React 的等待状态避免操作未完成时重复点击。
- 已买过的摆件仍可收到后续故事赠送的一件；故事完成标记继续防止重复领取。人物皮肤继续去重。
- `decorError` 同时用于地图预览和 Runtime 的最终提交，移动只忽略目标实例自身的占格，其他同种或异种物件都阻止重叠。

## 旧档兼容

schema 仍为 4；目录商品与既有配置指纹不变。旧存档缺少 `decorStock` 时，先按原规则验证种类来源、唯一摆件和有效地板，再补入库存：已拥有未摆放为 1，已摆放为 0，并给已有实例分配 ID。再次读档不重复增加数量，原有位置、货币、皮肤及故事保留。

新格式验证非负整数库存、已拥有种类对应关系、独立 ID 和序号、地板及占格，不再限制每类只能摆一件。没有沿用上轮开局时间变更的删档授权。
