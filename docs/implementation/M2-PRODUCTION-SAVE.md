- 新模式配置建材、食物、饮水、药品四类生产来源，以及一次性体力补给。图标使用新增 SVG，不覆盖原 TitanDemo 图标与表。

- 五张营地委托验证重复材料需求、跨棋盘 / 仓库扣料、物品奖励与晶石奖励。至多显示三张，交付立即在逻辑层补位，动画不决定扣料或发奖。它们不是正式主线剧情。
- 合成时营地日历和主角移动继续；界面显示时间、主角行动与体力。后台世界暂停，体力按真实时间恢复。体力 0 时仍可移动、合成、整理、使用补给和交付已有物品。
- 自然恢复每 10 秒 1 点，上限 100；道具可突破。达到或超过 100 不积累恢复额度，降到 100 以下重新计时。时钟回拨不扣体力。
- 正式加入 IndexedDB 保存与备份。返回、刷新和重新打开会恢复棋盘、仓库、奖励记录、移动路径 / 进度、世界时间、体力和随机状态；离线不补算世界。

尚未加入饥渴消耗、温度漂移、伤害、建造、夜袭、伙伴或主线剧情。当前生命 100，饱食 / 水分初值 60，温度 50，便于试用食物与饮水；这只是 M2 补给验收初值，不是最终新手平衡。食物 / 饮水 / 药品效果已经可用，对应状态满值时保留物品，不空耗。

## 状态与命令

- `GameRuntime` 持有唯一 ProductionState。React 只管理选择、弹层和拖拽浮层，不另存库存、体力或奖励副本。
- 实例 `iN` 与 itemId 分离；实例同时记录归属位置，棋盘 / 仓库格只存引用，校验禁止重复位置、游离实例与序号倒退。
- 物品操作使用实例 ID；拖拽还带期望落点 ID，扩容带期望容量，委托带稳定订单 ID。过期输入拒绝，不意外操作后来占据同一格子的物品。
- 命令在逻辑步按序提交。生产、合成、存取、使用、委托、奖励和随机状态同属一次事务；失败舍弃草稿，不部分扣资源。
- 订单统计已解锁且未预留的物品；重复需求逐枚匹配。领取标记与扣料、发奖一起保存，重复领取不能重复发奖。
- 预留字段及操作保护已建立，但本阶段不创建预留；M3 增加建造订单及其预留生命周期，并扩展 schema 校验。
- 指针取消不提交命令，仓库拖出后取消 / 无效落点会恢复仓库。普通手机九行适配可用高度；小屏保留格子可操作尺寸，并允许从空格或棋盘两侧滚动。

## 存档与故障边界

数据库 `wordmerge-survival`，object store 为 snapshots，记录 current、previous、revision。

- 当前 schemaVersion 为 1，configVersion 含地图与生产表指纹。M1 没有持久化旧档，因此无需迁移 M1。未知版本或配置不匹配会拒绝覆盖并允许导出原数据；下一阶段修改数据结构 / 配置时必须补明确迁移，不能按棋盘长度猜测兼容。
- 保存请求串行执行。一次 IndexedDB readwrite 事务比较 revision，并同时写入当前状态、上一有效备份和新 revision；任何写入失败都会中止整笔事务。
- 每个成功命令请求检查点；普通世界进度每约 2 活跃秒保存。切后台也请求检查点，但不把异步卸载写入当作绝对保证。
- 命令结果区分 accepted 和 persisted。保存失败时已接受的内存结果保留，世界暂停；用户可重试保存或导出备份，不重新执行造成失败的生产操作。
- 另一标签页抢先提交时，本页暂停并提示重新载入，不能通过“重试”覆盖对方。无账号 / 云存档 / 服务端时钟，本机数据不提供防篡改保证。
- 当前档结构损坏时读取上一有效备份并明确提示；两份都无效时保留故障记录，提供导出故障数据、导入旧备份和重试，不静默开新局。
- 导出 / 导入在“探索指引 → 本机存档”。导入校验 JSON、版本、配置、物品归属、关键来源、路径、体力锚点等，确认替换后先写入再切换当前状态；无效文件不改变进度。
- 本机存档依赖浏览器数据保留，清除站点数据会清除进度。异常终止仍可能丢失未提交的约两秒普通进度；不承诺绝对不回档。首版仍不承诺断网重新加载资源。
