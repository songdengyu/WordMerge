# TitanDemo 游戏规则基线

依据迁移时的 `ff54eba` 代码及正式 CSV 整理。这是旧游戏的实现说明，不代表 WordMerge 已决定保留全部系统。

## 核心循环与初始状态

战斗击杀获得金币 → 消耗金币使用合成生成器 → 拖拽合成并完成订单 → 获得装备、技能书、队友 → 提升战斗能力。钻石还可购买已配置价格的物品和扩容仓库。

初始金币 2000、钻石 5000；持有 `100010001` 和 `100020001` 各 1，装备第一个武器；无已解锁或上阵队友，自动战斗关闭。主角 `baseDps=0`，初始武器表内 `attack=2`，实际攻击属性读取已装备物品与被动技能。

## 战斗

- 点击战斗区域触发主角攻击；自动战斗打开后由主角自动出手。队友上阵后参与攻击。
- 每轮 9 个普通怪物后进入 Boss，怪物 ID 为 `(stage - 1) * 10 + 序号`，`id % 10 === 0` 为 Boss。旧 README 的“10 个普通怪物”已过时。
- `monsters.csv` 含 100 个怪物，覆盖 10 轮（不是 100 轮）。HP、掉金币、限时取配置；超出表范围仍有公式回退。
- Boss 超时失败后回到本轮普通怪起点并提示“Boss挑战失败，请重新历练”。主动撤退也回到普通怪，但保留随时“挑战 Boss”的入口，两条路径不能合并。
- 主角和队友伤害来自实际攻击事件；100ms 的 `useGameLoop` 推进计时等状态，并不直接把理论 DPS 每帧扣到怪物上。
- 怪物状态为 `fighting → dying → spawning → fighting`；死亡动画 650ms、出生动画 400ms，出生后有 0.2s 宽限。受击表现最小间隔 0.35s。
- 打开合成、武器或装备二级界面后暂停战斗和 Boss 倒计时；关闭恢复。战斗组件保持挂载。

伤害公式见 `src/data/combatStats.ts`：

```text
基础伤害 = 攻击力 × (1 + 攻击加成) × (1 + 伤害加成) × 技能系数
非暴击伤害 = 基础伤害 × (1 + 普攻伤害加成 或 技能伤害加成)
暴击伤害 = 非暴击伤害 × (2 + 暴击伤害增加)
期望伤害 = 非暴击伤害 × [1 + 暴击率 × (1 + 暴击伤害增加)]
```

暴击率结算时限制到 0–1。DPS 用期望伤害除攻击间隔，主角头像下的 DPS 向下取整显示；`power` 是装备战力展示，不直接乘入伤害。

## 合成棋盘

- 7 列 × 9 行，共 63 格；索引 `0..62`。`lock_state`：0 解锁、1 半锁、2 全锁。
- 相同 ID 且有 `next_id` 的棋子可拖拽合成，目标格留下升级结果、源格腾空。
- 解锁棋子可交换位置或移到空格；半锁棋子不能主动拖动，但可被同 ID 棋子合成解锁；全锁格不能直接交互。
- 合成解锁半锁格后，其上下左右的全锁格变为半锁，每个首次揭开的格子奖励 100 金币，用 `rewardClaimed` 避免重复领取。不是一次自动连锁揭开整个棋盘。
- 特殊棋子双击领取 100 金币并消失，同时触发邻格揭开逻辑。
- 拖动视觉跟随手指 / 鼠标，无效落点回弹；拖动与点击需要区分。棋子已取消独立背景框和可见等级标签，悬停 title 仍含等级。

## 生成器

- 最终操作为单击产出，并执行选择逻辑；早期“双击生成”“生成后消失”规则已经被替换。
- 只有同一合成链中，当前棋盘已解锁生成器的最高等级可以使用；同等级多个生成器均可能满足条件。另需配置 `open_cost` 和 `drop_pool`。
- 扣金币后按权重生成，生成器保留，产物随机放入已解锁空格；棋盘满时转入仓库并提示；棋盘与仓库均满时不扣费、不产出。
- 生成器不能通过存入操作放入仓库。

## 订单与仓库

- 最多并存 3 个订单，实际数量受 `max_concurrent` 控制。严格按连续订单 ID 推进，当前配置共 100 单，不无限循环。
- 卡片人物头像只是订单表现，不是队友派单 / 休息系统。
- 交付只扣除棋盘上已解锁的需求棋子，不扣仓库；重复需求需有对应数量。
- 发奖后播放订单离场动画，再补位。奖励读取 `equipment_id` 和 `quantity`，预览图与装备目录一致。
- 已拥有的非技能书奖励按 `dismantle_gold × quantity` 折成金币；类型 8 技能书允许累积。UI 判定与 reducer 的 `alreadyOwned` 参数共同完成该行为。
- 仓库初始 6 格，每次扩容 +3，钻石费用依次为 50、100、200、400、800、1600，最大 24 格。
- 取回仓库棋子时拖拽开始隐藏仓库，放到已解锁空格才成功；结束后重新打开仓库并提示结果。

## 装备、技能与英雄

`equipment_type` 的 1–7 分别为武器、副武器、头盔、衣服、腰带、鞋子、神器；8 为技能书，9 为队友。目录统一来自装备表，装备页展示七类入口，点击打开全屏选择页。

物品通过合成订单或配置的钻石价格获得；钻石价格为空表示不可购买。保留装备选择、替换、低战力提示及未持有灰态。

技能定义独立来自 `skills.csv`：类型 1 普攻、2 主动技能、3 被动技能；主角 owner ID 为 `100000001`。主角普攻默认至少 1 级，不应被技能书数量挡住初始攻击。技能书用于升级技能 / 队友；具体条件由 store 与技能表共同决定。

队友基础数值关联装备类型 9 数据，外观及攻击表现还依赖 `heroes.ts` 模板。平台容量常量为 18，不代表装备表已有 18 个可获得队友。

## 界面与保存边界

游戏容器为 1:2 竖屏，设计上限 1200×2400；战斗为底层画布，普通 tab 面板覆盖其上，关闭面板不应挪动战斗布局。列表独立滚动，toast 浮于界面上层。

合成页退出 / 再进入会通过全局 `mergeSnapshot` 恢复棋盘、订单及仓库，金币和钻石与全局同步。`persistMergeState` 仅清理并复制内存快照；项目没有 localStorage / IndexedDB / 服务端存档，刷新页面会重置。
